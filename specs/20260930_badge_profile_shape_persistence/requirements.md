# 需求规格说明书

> 状态：已确认

## 背景与目标

工牌网页已经支持方形、圆角和圆形照片，但形状只参与当次前端裁剪，没有写入设备。圆角或圆形的透明外围在转换 RGB565 时会合成到设备背景色；再次进入网页后页面固定选择方形，反显图便暴露近黑色外围。

本功能要把工牌照片形状与姓名、bio、图片作为同一份事务资料持久化。重新进入网页时应恢复对应选项，并按该形状重新裁剪反显图片，使预览与设备当前显示一致。项目仍处于开发阶段，本次不保留旧 Flash schema 或旧上传 envelope 的兼容逻辑。

## 功能需求

### R-01：定义并持久化工牌照片形状

- 工牌资料应包含 `square`、`rounded`、`circle` 三种稳定形状值。
- 新保存的形状应与姓名、bio、RGB565 图片处于同一双槽事务中；任何写入、校验或提交失败都不得发布部分更新。
- 形状只描述已经烘焙到图片中的遮罩，不改变图片格式、尺寸或设备端显示流程。
- 内置默认工牌的形状应明确为 `square`。

### R-02：查询并自动恢复形状

- `GET /api/profile` 应返回当前工牌形状。
- 网页读取 profile 后，应自动选中设备返回的方形、圆角或圆形选项。
- 网页读取 RGB565 照片后，应使用恢复的形状重新绘制预览；圆形和圆角的遮罩外近黑色像素不得继续暴露在预览中。
- 自动恢复不得改变设备上的已保存资料，只有用户主动保存时才产生新事务。

### R-03：上传形状并保持流式边界

- 新版工牌上传 envelope 应携带一个受严格校验的形状值。
- 前端保存时必须提交当前实际选中的形状，不得依赖默认值或从最终像素反推。
- 图片仍按块流式接收并直接写入非活动槽；不得在 ESP32 堆或任务栈中缓存完整 80,000 字节图片。
- 非法形状应在开始 Flash 事务前被拒绝，并返回稳定且不包含个人数据的错误。

### R-04：收敛为单一新版本

- 固件只读取新的工牌记录 schema 3；schema 1/2 视为无有效用户资料并回退到内置默认工牌。
- HTTP 只接受新的 envelope version 3；version 1/2 返回协议错误，不进入 Flash 事务。
- 启动时不得为清理旧格式而自动擦除 `badge_data`；首次新版保存继续使用双槽事务写入 schema 3。
- 内嵌网页与固件必须同步使用 version 3，并通过既有静态资源版本和禁缓存机制避免旧脚本继续提交。

### R-05：处理不可逆裁剪

- schema 3 资料重新进入网页时必须精确恢复形状，不使用像素颜色进行形状推断。
- 从圆形切换到圆角或方形、从圆角切换到方形时，网页应提示遮罩外原始像素无法恢复，并在重新选择原图前禁止保存。
- 从方形切换到圆角/圆形或从圆角切换到圆形时，可以继续使用当前图片进行更严格裁剪。
- 用户重新选择本地原图后，三种形状可自由切换，不显示丢失角落警告。

### R-06：保持现有工牌与个性化功能

- 工牌姓名、bio、拖动、缩放、旋转、连续保存及设备即时刷新行为保持不变。
- 三槽个性化图片 API、全屏图片、清空槽位和设备切图行为不受本功能影响。
- 热点地址、会话 token、Busy、超时、断连回退和按键退出行为保持不变。
- 日志和错误响应不得输出姓名、bio、照片、形状上传体或会话 token。

## 非功能需求

### NFR-01：存储与资源

- 不调整 `partitions.csv`、`badge_data` 地址或 `0x20000` 单槽大小。
- 新形状字段只把记录头从 40 字节扩展到 44 字节，不新增完整图片级 RAM、静态缓冲或 LVGL 图片副本。
- schema 3 的 payload 起点、两类 CRC 范围及 schema 1/2 拒绝路径必须有直接 native 测试覆盖。

### NFR-02：版本一致性

- 固件、内嵌网页、记录 schema 和上传 envelope 应统一为本功能的新版本，不保留旧版本条件分支。
- 旧记录失效时必须安全回退到当前默认资料，不得崩溃、自动擦除或读取错误图片偏移。
- 页面继续离线运行，支持 iPhone Safari 和 Android Chrome，不增加远程依赖。

### NFR-03：可验证性

- Native 测试应覆盖三种形状、非法值、schema 3 读取、旧 schema 拒绝、双槽轮换、重启恢复、CRC 和失败回退。
- HTTP 测试应覆盖 envelope version 3 的任意分块、旧 version 拒绝、非法形状、精确长度和事务失败。
- Web 测试应覆盖 profile 形状解析、radio 自动选中、按恢复形状重绘和扩大形状警告。
- 目标构建、Web/Native 自动化和真机浏览器结果必须分开报告。

## 验收标准

1. 分别保存方形、圆角和圆形工牌后，重新进入 `192.168.4.1`，对应选项自动选中。
2. 圆角和圆形照片反显时，已烘焙的近黑外围被相同形状遮罩隐藏，预览与设备显示一致。
3. 保存后重启设备并再次进入网页，形状、姓名、bio 和图片保持一致。
4. schema 1/2 旧资料不会被错误解析，设备安全回退到默认工牌且不自动擦除分区。
5. envelope version 1/2 在开始 Flash 事务前被拒绝。
6. 非法形状、Busy、断连或 Flash 失败不会发布半成品，上一份完整工牌仍可使用。
7. 圆形/圆角向更大形状切换时页面明确提示无法恢复角落，并在重新选择原图前阻止保存。
8. 三槽个性化、热点和设备按键回归行为保持不变。

## 范围外内容

- 不保存浏览器选择的原始 JPEG/PNG，不恢复已经被遮罩丢弃的原始角落。
- 不增加自定义圆角半径、背景颜色、边框、滤镜或更多形状。
- 不在设备端动态裁剪或增加 Alpha 通道。
- 不调整分区表、NVS schema、个性化图片记录、LCD 布局或 Wi-Fi 生命周期。
- 不用像素颜色进行无提示的强制形状识别。
- 不迁移或兼容 schema 1/2 工牌记录及 envelope version 1/2。

## 非阻塞实现参数

- 形状稳定值建议为：`square=0`、`rounded=1`、`circle=2`。
- 新 Flash 记录建议使用 schema 3；新 HTTP envelope 建议使用 version 3。
- schema 3 记录头扩展为 44 字节，shape 使用 2 字节元数据字段并保留 2 字节 reserved；payload 继续保持 `name + bio + image`。

## 待确认问题

无。用户已明确项目处于开发阶段，不要求旧 Flash 记录和旧上传协议兼容。
