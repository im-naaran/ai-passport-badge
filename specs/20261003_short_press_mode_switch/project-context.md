# 项目上下文

> 状态：已确认

## 项目与技术栈

- 项目是 ESP32-C3 展示侧固件，使用 ESP-IDF 5.5.3、PlatformIO、C11 与 LVGL 9。
- 设备有上、下、确认三个 ADC 按键。BSP 负责去抖和手势分类，短按在释放时产生 `BSP_BTN_CLICK`，按住 800 ms 产生一次 `BSP_BTN_LONG`，长按释放后不会再产生短按。
- 业务模式固定为“工牌”和“个性化”；“设置”位于业务模式循环之外。
- 个性化模式只有存在至少一个有效图片槽位时才可进入。

## 当前输入与导航链路

```text
BSP 按键边沿/定时器
  -> BSP_BTN_CLICK / BSP_BTN_LONG
  -> app_main 转换为 mode_key_t + long_press
  -> app_controller 处理唤醒、热点退出和渲染请求
  -> navigation_key 分配全局导航或页面局部操作
```

当前 `navigation_key()` 的语义为：

- 长按上/下：在可用业务模式间循环。
- 长按确认：进入设置；从设置返回时恢复进入前的业务模式，失效时回退到首个可用模式。
- 短按：转发给当前模式的 `handle_key()`。
- 设置页短按上/下移动栏目或选项，短按确认进入、保存或返回。
- 个性化页短按上/下在有效图片槽位间循环，短按确认不执行操作。
- 工牌页没有 `handle_key()`，三个短按均为 no-op。

## 相关模块

| 模块 | 当前职责 | 本功能相关性 |
|---|---|---|
| `components/bsp/src/button_gesture.c` | 50 ms 短按、800 ms 长按识别，保证长按释放不追加短按 | 原则上复用，不需修改阈值或底层事件 |
| `main/app_main.c` | 将 BSP 事件转换成语义按键并投递控制器 | 预计无需引入页面判断 |
| `main/app_controller.c` | 优先处理息屏唤醒和热点专页任意键退出 | 必须保持现有优先级 |
| `main/navigation/navigation.c` | 业务模式、设置页与页面局部操作的统一分流 | 本功能的主要设计与修改边界 |
| `main/navigation/mode.h` | 定义模式生命周期、局部按键处理与可用性 | 评估是否需要扩展显式输入策略 |
| `main/modes/custom/custom_mode.c` | 个性化槽位选择和当前槽位保持 | 若短按上/下改作模式切换，会直接发生职责冲突 |
| `main/settings/settings_page.c` | 设置列表、编辑页、热点页的局部输入 | 行为必须保持不变 |

## 现有公共能力与复用点

- 复用 `mode_t::handle_key` 承担页面局部操作，复用 `mode_t::is_available` 和 `adjacent_available()` 跳过不可用业务模式。
- 复用 `return_id` 保持设置返回目标，不增加第二套导航状态机。
- 复用 BSP 已有短按/长按互斥保证，不改变 ADC、手势阈值或事件队列。
- 复用 `display_activity_consume_gesture()`，保证息屏后的首次手势只唤醒、不触发模式或页面操作。
- 复用热点页在 `app_controller` 中的高优先级退出逻辑，任意语义手势仍只关闭热点并回到设置列表。

## 设计约束

- 设置页的短按上/下/确认语义必须完全保持。
- 个性化页现有短按上/下切图片槽位的语义，和“短按上/下切业务模式”占用相同输入，不能在同一页面状态下同时满足。
- 不应在 `app_main`、BSP 或 `app_controller` 中硬编码“工牌/个性化”的模式 ID；页面输入策略应由导航或模式描述表达。
- 不改变模式 ID、个性化可用性、设置返回、热点退出、息屏唤醒和渲染请求机制。
- 自动化测试只能证明状态机和构建边界；实体按键手感、LCD 切换和息屏唤醒仍需真机验收。

## 现有测试与验证入口

## 已知风险

- 若仅把 `navigation_key()` 中的 `long_press` 判断反转，个性化短按上/下会被全局导航抢占，已有切图能力回归。
- 若按页面 ID 写条件分支，后续增加业务模式时容易产生隐式规则并破坏导航通用性。
- 若长按不再承担任何功能但仍触发渲染，可能出现无状态变化的多余刷新；应明确长按的新语义并测试。
- 若短按切页发生在按键释放时，息屏唤醒消费必须仍覆盖该完整手势，避免唤醒后立即切页。
