# 需求规格说明书

> 状态：已确认

## 背景与目标

工牌首页和现有 Wi-Fi 工牌配置链路已经完成，但个性化模式目前只是不可进入的空白占位。用户需要通过同一个设备热点配置最多三张个性化图片，并在设备的 240×320 屏幕上以原生比例显示。

本功能目标是在不改变现有工牌配置逻辑的前提下，新增三个持久化个性化图片槽位、手机端所见即所得的全屏图片编辑与槽位选择，以及设备端图片浏览能力。容量评估已经确认当前 8 MB Flash 可以保留三槽，不采用 2 槽或 1 槽降级方案。

## 功能需求

### R-01：提供三个独立个性化图片槽位

- 设备应提供固定的 1、2、3 共三个逻辑槽位，每个槽位可为空或保存一张图片。
- 每个槽位独立更新；保存到一个槽位不得改写其他槽位或现有工牌资料。
- 已占用槽位允许被新图片覆盖，覆盖成功后展示新图片；保存失败时继续保留该槽位上一张完整图片。
- 已占用槽位允许被用户主动清空；清空只影响目标槽位，不能删除其他槽位或工牌资料。
- 清空操作也必须具备事务语义；清空过程中断电、断连或写入失败时，目标槽位应保持清空前的完整图片，不能进入无法判定的新旧状态。
- 冷启动和重启后应恢复各槽位的占用状态与最后成功保存的图片。
- 本期不因用户只使用一张或两张图片而占用额外 RAM；未使用槽位保持为空。

### R-02：个性化页面以屏幕原生尺寸展示图片

- 个性化图片固定为 240×320、3:4 竖向比例、RGB565 LE，对应 LCD 物理像素 1:1 显示。
- 图片应占满个性化页面，不额外叠加标题、槽位编号、边框或操作提示，以免遮挡用户内容。
- 设备端不缩放、不裁剪、不解码 JPEG/PNG；所有构图在浏览器保存前完成。
- 切换图片后不得出现上一张图片残影、短暂错误尺寸或访问失效 Flash 指针。

### R-03：根据有效槽位控制页面可用性与浏览

- 当三个槽位均为空时，个性化模式保持不可用，长按上/下仍停留在工牌页，不进入空白页。
- 任一槽位保存成功后，个性化模式自动变为可用，无需重启。
- 从工牌页长按上或下进入个性化页时，显示第一个有效槽位；若本次开机期间曾在个性化页浏览，则优先恢复最近显示且仍有效的槽位。
- 个性化页中短按上/下应只在有效槽位间反向/正向循环，跳过空槽位；只有一张有效图片时短按为无视觉变化的 no-op。
- 清空当前图片对应槽位后，若仍有其他有效槽位，则下次进入个性化页显示最近的有效槽位；若三个槽位均已为空，则个性化模式立即变为不可用，退出设置时安全回退到工牌页。
- 长按上/下仍用于工牌与个性化模式切换，长按确认仍进入设置；短按确认在本期不执行操作。

### R-04：在现有 Wi-Fi 页面新增个性化配置入口

- 热点启动方式、SSID、`http://192.168.4.1/`、会话 token、任意设备按键退出和热点关闭逻辑保持不变。
- 配置网页应清晰区分“工牌配置”和“个性化配置”；默认仍进入工牌配置，现有工牌字段、照片形状和保存行为保持不变。
- 个性化配置应展示三个可选择槽位，并明确标识各槽位为空或已有图片。
- 切换到已有图片的槽位时，网页应从设备读取该槽位图片并反显到编辑画布；切换到空槽位时显示空状态，不沿用另一槽位的图片。
- 已占用槽位应提供“清空槽位”操作；空槽位不显示或禁用清空操作。
- 清空前必须显示包含目标槽位编号的二次确认，避免误触；用户取消确认时不得向设备发送清空请求。
- 工牌表单与个性化表单必须使用独立编辑状态和保存动作，不能把工牌图片误存到个性化槽位，或把个性化图片提交到工牌 API。

### R-05：浏览器端完成个性化图片构图

- 用户可从手机选择常见 JPEG/PNG 等浏览器可解码图片；原图不上传到设备。
- 前端提供 240×320、3:4 的实时预览画布，并采用 cover 方式填满画布。
- 用户可在画布中拖动图片、以 1～4 倍缩放、按 90° 旋转；每次操作应立即反映到预览。
- 前端固定控制最终输出为 240×320 RGB565 LE、153,600 字节，不允许用户提交任意宽高或横向画布。
- 预览结果与设备保存后的全屏显示应保持一致；浏览器常见 EXIF 方向应沿用当前解码兼容策略。
- 为避免手机内存峰值，网页一次只加载和编辑当前选中槽位，不同时解码三个槽位图片。

### R-06：选择目标槽位并保存

- 用户必须明确选择 1、2、3 中的目标槽位后才能保存个性化图片。
- 保存按钮应同时受“设备会话有效、当前有图片、目标槽位有效、未处于上传中”约束。
- 保存请求应携带目标槽位、固定格式和固定图片长度，并继续使用当前热点会话 token。
- 设备应按块接收并直接写入目标槽位的非活动副本，不在堆中缓存完整请求体。
- 保存成功后，网页应更新该槽位为已占用并继续反显保存结果；设备应刷新个性化内容状态。
- Busy、非法槽位、非法长度、token 失效、超时、断连或 Flash 写入失败时，应提供稳定且不泄露图片内容的错误反馈。
- 清空请求应携带目标槽位并继续校验当前热点会话 token；上传或另一清空事务进行中时返回 Busy，不允许并发修改槽位。
- 清空成功后，网页应把目标槽位置为空状态并清除该槽位画布；清空失败时继续反显原图片，并提示原内容仍保留。

### R-07：独立持久化与事务安全

- 新增独立 `custom_data` 数据分区，不扩写或重解释 `badge_data` 和 `cardid`。
- 三个逻辑槽位各自使用双副本事务记录，记录至少校验 magic、schema、槽位、图片格式、宽高、stride、长度、sequence、payload CRC、header CRC 和提交标记。
- 记录发布顺序必须为：擦除目标非活动副本、写头和图片、读回校验、最后写提交标记。
- 清空槽位不得通过同时擦除两个物理副本实现；应写入带新 sequence 的已提交“空槽墓碑”记录，使掉电前后的状态均可确定，并允许后续上传继续复用双副本轮换。
- 启动时每个逻辑槽位分别选择最新有效副本；一个槽位损坏不得使另外两个槽位失效。
- 分区不存在或初始化失败时，固件应继续提供工牌与设置功能，个性化模式保持不可用，并记录不含用户图片内容的诊断信息。

### R-08：保持现有功能与安全边界

- `GET /api/profile`、`GET /api/photo`、`POST /api/profile` 的协议和工牌行为保持兼容。
- Wi-Fi/HTTP/Flash 回调不得直接操作 LVGL；保存完成后通过应用事件更新模式状态和请求渲染。
- 工牌页、设置页、电量、亮度、息屏、热点安全退出、唤醒手势消费和按键长按语义不得回归。
- 日志不得输出个性化图片数据、HTTP body、会话 token、原文件名或能够恢复用户图片的内容。
- 普通构建和上传不得擦除 NVS、`badge_data`、`custom_data` 或 `cardid`；禁止把全片擦除作为升级步骤。

## 非功能需求

### NFR-01：容量与内存

- 正式方案必须支持三个槽位；只有实际分区边界或目标构建证据推翻当前计算时，才回到需求阶段讨论降为两个，最后才讨论一个。
- `custom_data` 建议为 `0x100000`，其中六个 `0x28000` 物理记录支持三个逻辑槽位双副本，并保留 64 KiB 余量。
- ESP32 运行时不得为三张图片建立完整 RAM 副本；显示路径应使用 Flash 映射，上传使用小块缓冲。
- 新功能不得使 3 MiB 应用分区溢出；需记录目标构建后的 Flash 和静态 RAM 变化。

### NFR-02：兼容性与体验

- 配置网页继续离线运行，支持常见 iPhone Safari 与 Android Chrome 竖屏操作，不依赖 CDN、远程字体或互联网。
- 240×320 编辑画布应适配常见手机窄屏，不产生阻止保存按钮操作的横向溢出。
- 现有 200×200 工牌裁剪、拖动、缩放、旋转、方形/圆角/圆形和 bio 编辑均保持原行为。
- 个性化页面切图应在用户可接受时间内完成；目标为按键后下一次有效渲染即显示目标图，无额外解码等待。

### NFR-03：可测试性与证据

- native 测试应覆盖：三槽独立性、双副本选择、sequence 回绕、CRC/提交损坏、覆盖失败回退、清空墓碑、清空失败回退、空槽跳过、单图 no-op、多图按键循环和模式动态可用性。
- HTTP 测试应覆盖：槽位元数据、三张图片读取、保存与清空的非法槽位、固定长度、分块边界、Busy、token、断连/超时/失败回退及内容更新事件。
- Web 测试应覆盖：240×320 cover 几何、拖动边界、旋转后几何、RGB565 长度、槽位状态隔离、已有图片反显、保存目标、清空二次确认/取消/成功/失败和现有工牌 200×200 回归。
- 必须执行分区布局校验，证明应用、`badge_data`、`custom_data`、`cardid` 均不重叠且位于 8 MB Flash 内。
- `pio run` 只作为编译、链接和资源占用兜底；LCD、实体按键、iPhone/Android、真实上传耗时、断电恢复和普通烧录数据保留需单独验收。

## 验收标准

1. 分区和目标构建证据确认设备支持三个 240×320 图片槽位，不影响 3 MiB 应用、工牌资料或 `cardid`。
2. 三槽均为空时无法进入个性化页；任一槽保存后无需重启即可通过长按上/下进入。
3. 个性化图片以 240×320 全屏 1:1 显示，无标题、边框、拉伸、裁切偏差或上一张残影。
4. 短按上/下只在有效槽位间循环，跳过空槽；全局长按切页、进入设置和唤醒行为不变。
5. 访问 `192.168.4.1` 后可在原工牌配置和新增个性化配置之间切换；原工牌完整流程保持正常。
6. 网页可选择目标槽位、选择图片、拖动、缩放、旋转，并以 3:4 画布反显；保存后的 LCD 构图与预览一致。
7. 已有槽位图片可重新读取、反显和覆盖；切换空槽不会错误沿用其他槽位内容。
8. 已占用槽位可在二次确认后清空；取消确认不发请求，清空一个槽位不影响其他槽位，清空最后一个槽位后设备回退工牌且个性化页不再可进入。
9. 任一目标槽上传或清空失败、断连或掉电时，该槽清空前的已提交图片及其他槽位均保持可用。
10. 重启后恢复三槽占用/清空状态和图片；工牌资料、设备设置与 `cardid` 保持不变。
11. 新增聚焦测试、现有全量 native/Web 回归、分区检查和目标构建完成；真机结果与自动化证据分开记录。

## 范围外内容

- 本期不支持第四张及更多图片，不根据剩余容量动态增加槽位。
- 本期不为个性化图片增加文字、贴纸、滤镜、边框、形状遮罩、背景色或多图拼接。
- 本期不保存 JPEG/PNG 原图，不在设备端解码、缩放或裁剪图片。
- 本期不增加自动轮播、定时切图、动画转场、槽位名称或开机直接进入个性化页。
- 本期不新增 BLE、云同步、互联网访问、热点密码或跨设备同步。
- 本期不修改现有工牌资料 schema/envelope，也不迁移 `badge_data`。

## 非阻塞实现参数

- 槽位编号：用户界面显示 1～3，协议和内部数组可使用 0～2，但边界必须集中转换并测试。
- 图片格式：240×320、stride 480、RGB565 LE、153,600 字节。
- 页面构图：cover 填充，缩放范围 1～4 倍，旋转步长 90°。
- 进入个性化页：优先当前开机期间最近有效槽位，否则选择编号最小的有效槽位。
- 页面视觉：全屏纯图片，不显示槽位指示器。
- 分区建议：`custom_data@0x35A000/0x100000`，数据 subtype 使用项目自定义值且不得与 `badge_data` 冲突。

## 待确认问题

无。若用户希望本期同时支持自动轮播或图片上的槽位提示，需要在确认本阶段前加入需求；否则按上述范围进入技术设计。
