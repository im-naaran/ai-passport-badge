# 需求规格说明书

> 状态：已确认

> 交付范围调整（2026-09-27）：普通 PlatformIO 构建与上传入口是必要交付，同时保留直接覆盖核心业务逻辑的 C/Unity native 测试。Node Web 测试、布局/仓库检查、统一验证脚本、角色副本产物和单文件工厂镜像不再作为当前精简工程的交付内容；历史设计与验收边界保留用于追溯。

## 背景

最后开发的综合固件同时包含工牌、消息、音乐、Wi-Fi/HTTP、BLE/ANCS/AMS 和 LVGL 页面。ESP32-C3 无 PSRAM，综合镜像不仅体积和运行时内存压力较大，还为 BLE/Wi-Fi 动态停止与恢复引入了异步 timer、event queue 和 callback 生命周期风险。

项目已决定拆为互相独立的展示固件与手机伴侣固件。消息和音乐已由另一固件承载；本仓库需要从官方 Demo 骨架和最后开发代码中选择性迁移展示侧能力，形成只含工牌、空白个性化页、通用设置及 Wi-Fi 工牌配置的独立固件。

## 目标

- 建立可独立构建、测试、烧录和识别的 AI Passport 个性展示固件。
- 冷启动直接显示工牌，并保留独立的空白个性化占位页。
- 保留亮度、自动息屏、电量显示等展示侧通用能力。
- 通过按需开放的本地 Wi-Fi 网页配置照片和姓名，可靠保存用户工牌。
- 在编译与链接层彻底排除 BLE、ANCS、AMS、消息和音乐能力，降低 Flash、静态 RAM、运行时堆及生命周期复杂度。
- 保持 NVS、工牌资料和 `cardid` 的升级与跨固件切换安全。

## 功能需求

### R-01：建立独立展示固件工程

当目标仓库完成迁移后，系统应当能够不依赖 `_ai-passport-tools_dev/` 目录独立构建展示固件。

- 工程以官方 Demo 的硬件、受保护布局和验证约束为基线，选择性迁移旧开发固件的展示侧能力。
- 启动日志和可见版本信息应明确标识展示固件角色，避免与消息/音乐固件混淆。
- 参考目录不得成为编译 include、链接、资源加载或发布包的运行时依赖。
- 根 `.gitignore` 应在迁移生产文件前建立，排除本地参考目录、系统元数据、构建输出、生成配置、依赖缓存和常见 IDE 文件。

### R-02：提供双业务页导航

当设备冷启动或用户在业务页操作时，系统应当只提供“工牌”和“个性化”两个业务页。

- 默认首屏为工牌。
- 长按下在“工牌 → 个性化 → 工牌”之间循环，长按上反向循环。
- 长按确认进入设置；设置页不加入业务页循环，退出设置回到进入前的业务页。
- 工牌页短按上、下、确认均不修改资料。
- 页面使用稳定内部 ID，不依赖注册数组下标表达业务身份。

### R-03：展示默认与用户工牌

当设备没有有效用户记录时，系统应当显示固件内置默认工牌；当存在有效用户记录时，系统应当显示用户照片和姓名。

- 工牌照片固定为 200×200 RGB565 展示区域，不拉伸、不越界。
- 姓名单行居中，保存前按 UTF-8 字节和字符规则校验，不依赖 UI 静默截断。
- 默认工牌包含明确的占位照片、默认名称和默认展示文案；用户工牌只显示用户照片和姓名。
- 页面对象创建后复用，切页、设置修改和后台电量更新不得反复创建图片对象。
- 新资料提交成功后无需重启即可刷新；不在工牌页时，下次进入显示最新快照。

### R-04：事务化保存工牌资料

当系统加载或保存工牌资料时，系统应当使用独立 `badge_data` 分区中的版本化双槽记录，并在错误或断电后回退到完整记录。

- 沿用 `badge_data@0x310000/0x40000`，每个槽 `0x20000`；不得移动、扩大或覆盖 `cardid@0x356000/0x4000`。
- 记录至少校验 schema、提交序号、姓名长度、图片格式、尺寸、长度、CRC 和提交状态。
- 新资料先写非活动槽，读回并校验成功后才成为活动记录。
- 两槽均无效时回退默认工牌；不得自动格式化 NVS、擦除其他固件的绑定数据或执行全片擦除。

### R-05：从设置页管理展示侧配置

当用户长按确认进入设置时，系统应当只显示展示固件相关项目。

- 设置列表至少包含“Wi-Fi 热点”“自动息屏”“屏幕亮度”“返回”。
- 不显示消息容量、消息过期、BLE、ANCS、AMS 或音乐相关项目。
- 亮度使用旧固件已支持的 20%/40%/60%/80%/100% 档位，默认 60%，保存后立即生效并持久化。
- 自动息屏使用已有合法档位和持久化语义；唤醒后恢复已保存亮度。
- 读取到旧 schema 或其他 profile 的未知字段时，只迁移已知合法通用字段，不清除整条 NVS 或其他 namespace。

### R-06：按需启动和关闭 Wi-Fi 配置热点

当用户在设置页选择“Wi-Fi 热点”时，系统应当启动只服务于工牌配置的 SoftAP 和 HTTP 服务。

- 热点默认不开机自启，无密码，最多允许一个客户端；SSID 使用 `AI-Passport-XXXX` 形式，地址为 `192.168.4.1`。
- 专用 Wi-Fi 页显示启动中、等待手机、手机已连接、保存成功、启动失败和关闭状态。
- 保存成功后热点继续开放，允许连续修改；不设置无操作自动关闭计时。
- 用户在专用 Wi-Fi 页按任意实体键时退出页面并请求关闭热点，且该次按键不得触发其他设置或导航行为。
- 若正在写入，界面可立即退出，但底层必须等当前事务到达安全边界后再停止 HTTP/Wi-Fi。
- 启停流程只管理 Wi-Fi/HTTP/netif/event 资源，不包含停止、销毁、重建或恢复 BLE 的状态和代码。

### R-07：提供离线工牌配置网页

当手机连接热点并访问 `http://192.168.4.1/` 时，系统应当返回无需互联网的工牌配置网页。

- HTML、CSS 和 JavaScript 全部内嵌，不引用 CDN、远程字体、统计或云接口。
- 页面适配常见 iPhone Safari 和 Android Chrome 竖屏宽度。
- 页面提供照片选择、拖动、缩放、90° 旋转、正方形预览、姓名输入、保存进度和错误反馈。
- 浏览器负责图片解码、方向调整、裁剪、缩放和 RGB565 转换；设备不保存原图，也不启用通用图片解码器。
- 未知路径、非法方法、过大 body、无效 token 和错误内容返回受控结果；页面不能访问设置、身份区或其他固件数据。

### R-08：校验和串行处理配置上传

当网页提交姓名和图片时，系统应当在固定内存上限内流式校验并串行保存，只有完整事务成功后才发布新工牌。

- 姓名必须为 1～48 个合法 UTF-8 字节，不能包含控制字符或换行。
- 图片必须严格为 200×200、RGB565 LE、80,000 字节；协议版本、长度和 CRC 必须匹配。
- HTTP body 按块接收并直接写入目标事务，不同时完整持有原图、转换图和整个请求体。
- 同一时间只允许一个写事务；重复提交返回稳定 Busy 语义。
- 客户端断开、超时、取消、额外数据、Flash 或校验错误均不发布半成品，上一份有效工牌保持可用。
- HTTP、Wi-Fi 和存储回调不直接访问 LVGL；成功事件由应用上下文消费并请求渲染。

### R-09：保留空白个性化占位页

当用户切换到“个性化”页时，系统应当显示独立、稳定且可返回的空白占位页面。

- 本期不定义个性化记录格式、图片/文字内容、网页入口或上传接口。
- 个性化页不得复用工牌资料冒充个性化内容，也不得为未来能力预留大块运行时缓冲。
- 后续实现个性化内容时必须另立需求规格，并在编码前确定内容模型与 Flash 布局。

### R-10：在构建和链接层排除手机伴侣能力

当生成展示固件时，构建系统应当不编译、不链接、不初始化消息、音乐和蓝牙相关能力。

- 组件依赖中不得包含 `bt`；应用不得初始化 NimBLE、ANCS 或 AMS。
- ELF/Map 中不得出现 `nimble_port_*`、`ble_session_*`、`ancs_*`、`ams_*`、消息存储或音乐服务业务符号。
- 不迁移 `wireless_mode`、BLE stop/restart 路径、重连退避或“关闭/恢复蓝牙”反馈。
- 不允许仅通过隐藏页面、运行时分支或不调用初始化来声称完成拆分。

### R-11：保留显示、电量与省电基础能力

当设备运行、息屏或被按键唤醒时，系统应当保留展示侧所需的电量、背光、显示休眠/恢复和变化驱动渲染能力。

- 顶栏显示当前页名称和电量百分比；电量不可用时显示明确占位，不伪造数值。
- 自动息屏应暂停显示活动、关闭背光并可逆地让 LCD/LVGL 进入低活动状态；按键唤醒后同步呈现首帧再恢复保存亮度。
- 电量采样和页面更新按状态/变化驱动，不以无意义高频全屏刷新维持 UI。
- 不通过增大 LVGL 24 KiB 内存池解决对象过多或生命周期错误。

### R-12：提供安全构建、烧录与文档入口

当开发者构建、测试或切换固件时，项目应当提供单一、可复现的展示固件工作流，并明确保护持久数据的边界。

- 构建产物名称包含展示固件角色，输出应用 Flash、静态 RAM 和镜像大小。
- 布局检查验证 3 MB 应用上限、分区表、`badge_data` 和 `cardid`，并包含越界负例。
- 对已配置设备使用不覆盖 NVS、`badge_data` 和 `cardid` 的安全烧录方式；不得建议全片擦除。
- README 说明功能范围、按键、热点配置、开放网络风险、构建/烧录命令、资料保留和手机伴侣能力不在本镜像中。
- 构建、host 测试、布局验证和真机验收必须分别报告，不得用前者替代 LCD、手机、掉电或功耗证据。
- 仓库文档、源码、配置、测试夹具及日志示例不得包含本机用户主目录等隐私绝对路径；命令使用相对路径、通用占位符或运行时项目根目录。

## 非功能需求

### NFR-01：资源边界

- 目标设备无 PSRAM；迁移应优先减少链接依赖、常驻任务、队列、字体副本和运行时缓冲。
- 工牌页保持低对象数，Web 资源使用构建期内嵌，不引入设备端通用图片解码、文件系统或第二套 UI 框架。
- 构建记录 Flash/静态 RAM；真机记录冷启动、热点关闭、热点运行和连续保存后的普通堆、最大连续块、DMA 堆与关键任务栈水位。

### NFR-02：可靠性

- 冷启动、反复双页切换、反复进入/退出设置、至少五轮热点启停和连续保存不得白屏、重启、watchdog 或持续泄漏。
- Wi-Fi/HTTP 启动中途失败必须逆序释放已创建资源并允许再次尝试。
- 未识别 schema、损坏记录和 I/O 失败不得触发整片或整分区自动擦除。

### NFR-03：安全与隐私

- 开放热点只由设备实体入口启动，并持续显示其开启状态；文档明确其不提供认证、保密或互联网。
- 所有长度、乘法、偏移和写入范围在写 Flash 前检查溢出与边界。
- 日志不输出姓名、照片内容、完整请求、会话 token、设备身份数据或其他可复用秘密。

### NFR-04：可维护性

- 共享硬件能力留在 BSP；业务页面、状态机、协议、资源和任务留在应用层。
- profile 差异通过源清单和清晰入口表达，不在业务函数中散布大量条件宏。
- 单次使用的简单逻辑不抽取公共封装；迁移公共能力前记录其来源、差距和适配原因。
- 生产代码和发布流程不得依赖参考目录；参考来源与许可证必须可追溯。
- `.gitignore` 和仓库静态检查共同防止本地参考目录、生成物及个人绝对路径进入版本控制。

### NFR-05：可验证性

- 纯逻辑测试至少覆盖工牌记录、UTF-8 姓名、序号回绕、双槽选择、中断写入、Wi-Fi 状态、HTTP 流式协议、设置迁移、导航和显示调度。
- Web 测试至少覆盖裁剪坐标、缩放边界、旋转、固定输出尺寸、RGB565 转换、表单边界、Busy 和错误反馈。
- 静态隔离检查解析实际 ELF/Map 或链接结果，不只搜索源码目录。
- 真机验收单独覆盖 LCD、实体键、热点、iPhone Safari、Android Chrome、断电恢复、资料保留、资源趋势和功耗。

## 验收标准 / 人工确认点

### AC-01：独立镜像与静态隔离

Given 目标仓库不提供参考目录作为构建输入，When 执行完整展示固件构建与符号检查，Then 构建成功且 ELF/Map 不含 BLE、ANCS、AMS、消息和音乐依赖或业务符号，并输出独立的展示固件产物。

### AC-02：冷启动与双页导航

Given 设备刷入展示固件，When 冷启动并使用长按上/下与长按确认，Then 默认显示工牌，只在工牌与空白个性化页间循环，设置可进入并返回原业务页，短按不会误改工牌。

### AC-03：默认与用户工牌

Given 分别处于无有效用户记录和已有有效用户记录状态，When 打开工牌页，Then 前者显示完整默认工牌，后者显示 200×200 用户照片和合法姓名，切页及设置变化不产生白屏、拉伸或对象持续增长。

### AC-04：网页裁剪和连续保存

Given 用户从设置启动热点并连接手机，When 在 iPhone Safari 或 Android Chrome 打开 `192.168.4.1`、裁剪/旋转照片、填写姓名并连续保存多次，Then 网页与设备预览方向和构图一致，每次成功后设备热更新且热点保持开放。

### AC-05：异常上传与热点退出

Given 已存在有效旧工牌，When 提交空/超长/非法姓名、损坏或错误长度图片、重复请求、断网、超时，或上传中按键退出，Then 系统给出稳定错误或安全结束连接，不发布半成品，旧工牌继续有效，资源最终释放且可重新进入热点。

### AC-06：掉电恢复与受保护数据

Given 已有有效工牌及设备持久数据，When 在新记录写入、校验和提交阶段分别断电，或在展示/手机伴侣固件之间使用安全分段流程切换，Then 设备只选择完整新记录或旧记录，NVS、`badge_data` 和 `cardid` 不被普通刷写覆盖。

### AC-07：设置、息屏与唤醒

Given 用户修改亮度和自动息屏，When 保存、等待息屏、按键唤醒并重启，Then 设置保持、息屏生效、唤醒首帧完整且恢复保存亮度，电量显示不会与页面内容重叠。

### AC-08：资源稳定性

Given 设备已刷入展示固件，When 完成至少五轮热点开启、连接、保存和退出，并持续切页/息屏/唤醒，Then 无崩溃、watchdog 或持续堆下降；资源记录可区分构建指标与真实运行时指标。

## 范围外

- 消息、音乐、BLE、NimBLE、ANCS、AMS、iPhone 配对和手机伴侣固件实现。
- 个性化页的图片、标题、副标题、多模板、动画、二维码、自由排版、持久化和网页配置。
- Wi-Fi STA、互联网访问、云同步、遥测、HTTPS、OTA 和自动 Captive Portal。
- 设备端任意图片格式解码、EXIF 解析、自由尺寸缩放或保存手机原图。
- 工牌资料恢复默认/清除菜单；不得用全片擦除替代该能力。
- 本期主动迁移或清理旧参考工程的 Git 状态、历史综合固件和手机伴侣固件。

## 待确认问题

### 阻塞性问题

无。

### 非阻塞假设

- A-01：本仓库只产出单一展示固件，不在同一仓库继续维护 `ai_passport_phone` 构建目标；若后续希望两镜像共仓维护，需要重新评估公共源码和构建布局。
- A-02：个性化本期按用户所述保持为空，仅提供可导航的独立占位页；内容模型延期到后续规格。
- A-03：设置页删除消息容量和消息过期，只保留热点、息屏、亮度和返回；若还需其他通用设置，可在设计确认前补充。
- A-04：默认工牌暂沿用旧开发固件的非个人化占位资源与 `AI Passport` 文案；正式品牌素材可在实现阶段按用户提供资源替换。
- A-05：Phase 2 将比较“官方 Demo 原生 ESP-IDF 骨架 + 迁移旧模块”和“沿用旧 PlatformIO 工程后做链接级裁剪”的成本，但无论选择哪条路径，都必须满足独立构建、静态隔离和保护分区要求。
