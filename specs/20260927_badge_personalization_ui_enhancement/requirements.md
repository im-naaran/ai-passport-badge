# 需求规格说明书

> 状态：已确认；实现与自动化验证已完成，真机验收待用户执行

## 背景与目标

当前工牌展示固件的工牌和 WiFi 配置已可正常使用，但公共顶部栏持续占用 36 px，并展示可由默认工牌身份推断出的标题；空白个性化页仍可被切入；电量长期占据业务页右上角；用户工牌资料只有照片和姓名；网页照片输出也只有方形。

本次改进目标是让默认工牌页面更完整、导航只进入有内容的模块、把设备状态集中到设置页，并在保持现有事务存储与固定 RGB565 图片边界的前提下增加自定义语句和三种照片形状。

## 功能需求

### R-01：移除公共顶部标题栏

- 设备业务页不再显示公共顶部栏、当前模块标题或右上角电量。
- 工牌是冷启动和默认业务模块，不需要额外显示“工牌”标题。
- 移除顶部栏后，业务页面应使用完整 240×320 显示区域，不保留 36 px 空白或分隔线。
- 设置页应在自身内容内提供足以识别页面用途的“设置”标题，但不恢复跨页面公共顶部栏。
- 页面切换、息屏唤醒和局部刷新后不得残留旧标题、电量或分隔线像素。

### R-02：仅在个性化有内容时允许切换

- 长按上/下用于在当前可用的业务模块之间切换；长按确认仍进入设置。
- 当个性化模块无内容时，从工牌页长按上或下均保持在工牌页，不显示空白个性化页。
- 当前版本没有个性化数据模型，默认应判定为无内容。
- 导航必须保留个性化稳定模式 ID 和未来启用能力；内容状态将来变为可用时，无需重写按键分派即可参与上下切换。
- 不可用模式不得成为设置页的返回目标；从设置返回应回到进入设置前的有效业务模块。
- 因当前只有工牌一个可用业务模块，按上/下保持当前页时不要求弹出“无个性化内容”等提示。

### R-03：在设置页展示电量

- 工牌页和个性化页不显示电量。
- 设置列表页应展示最近一次有效电量百分比；没有有效读数时显示 `--%`。
- 电量是只读状态，不占用可选择行，不参与上/下光标循环，也不能被确认键编辑。
- 电量低于或等于 15%、16%～30%、高于 30%及不可用状态应沿用现有危险、警告、普通、弱化颜色语义。
- WiFi 配置专页和亮度/息屏编辑页无需重复显示电量；返回设置列表后显示最新值。
- 电量采样周期、CW2017 后台任务和失败重试策略保持不变。

### R-04：为工牌增加自定义语句

- 工牌资料由照片、姓名和一条可选自定义语句组成。
- 自定义语句允许为空；非空时必须是合法 UTF-8，不得包含 C0 控制字符、DEL、换行或回车。
- 自定义语句上限暂定为 96 个 UTF-8 字节；网页应显示实时字节计数并在超限时阻止保存。
- 用户工牌在姓名下方显示非空自定义语句；空字符串时不显示占位文案。
- 自定义语句最多显示两行，居中排版；必须与照片、姓名保持清晰间距且不越出 240×320 屏幕。
- 内置默认工牌继续显示既有默认语句“我的 AI 身份”，并通过与用户资料相同的资料字段/渲染语义呈现，避免仅对默认资料做 UI 特判。

### R-05：在 WiFi 配置网页编辑自定义语句

- 工牌配置网页在姓名字段下增加“自定义语句”输入框和 UTF-8 字节计数。
- 页面初始化时应从设备读取当前自定义语句；旧工牌资料或默认资料没有用户语句时按对应快照值展示。
- 保存时照片、姓名和自定义语句应属于同一个事务；任一字段非法或写入失败都不得发布部分更新。
- 保存按钮状态必须同时考虑照片、姓名、自定义语句和上传中状态；自定义语句为空不阻止保存。
- 错误反馈应区分姓名非法与自定义语句非法，且不向日志或错误响应回显个人文本。

### R-06：兼容演进工牌记录与上传协议

- 新工牌记录应保存自定义语句长度和字节，并继续校验 schema、字段长度、图片元数据、payload CRC、header CRC 与提交标记。
- 现有 schema 1“姓名 + 图片”双槽记录必须继续有效，读取时将自定义语句解释为空字符串；不得要求擦除 `badge_data` 或重新上传。
- 新写入继续使用原有双槽事务、非活动槽、读回校验和最后提交标记，不改变分区地址和槽大小。
- 新 HTTP envelope 应携带自定义语句长度，保持固定最大 body、会话 token、单写事务和按块流式解析。
- 设备端至少应为当前内嵌网页提供一致的新协议；旧协议的写入兼容策略在设计阶段确定，但不能破坏旧 Flash 记录读取兼容。
- `GET /api/profile` 应返回自定义语句，同时继续返回姓名、尺寸和默认资料标志。

### R-07：支持方形、圆角和圆形照片输出

- WiFi 配置网页应提供“方形”“圆角”“圆形”三种互斥照片形状，默认选择方形。
- 形状切换由前端 JavaScript 控制，并立即反映在 200×200 Canvas 预览中。
- 方形保留完整 200×200 输出；圆角暂定固定 24 px 圆角半径；圆形使用以画布中心为圆心、直径 200 px 的遮罩。
- 圆角和圆形在网页预览中的遮罩外区域应透明；上传时将透明像素合成到设备工牌页背景色，设备上不得出现白色外圈。最终上传仍是无 alpha 的 200×200 RGB565 LE、80,000 字节图片。
- 形状效果应烘焙进最终上传像素，设备端不新增图片形状字段、不在 LVGL 运行时裁剪，也不增加设备端图片内存。
- 选择新照片、拖动、缩放、旋转和切换形状后，预览与最终提交必须一致。
- 页面读取已有照片后，即使用户不重新选图，也应允许切换形状并保存；无法可靠从既有 RGB565 像素反推原始形状时，形状控件可回到默认“方形”。

### R-08：保持现有交互和安全边界

- WiFi 热点仍只能从设置页主动开启；SSID、地址、单客户端、连续保存和任意设备按键退出行为不变。
- 照片仍由浏览器解码、裁剪和转换；设备不保存原图、不引入通用图片解码器。
- HTTP/WiFi/Flash 回调不得直接操作 LVGL；保存完成后仍通过应用事件请求刷新。
- 长按确认进入设置、息屏首个手势仅唤醒、亮度/息屏编辑、热点安全关闭等现有行为不得回归。
- 日志不得输出姓名、自定义语句、照片、HTTP body 或会话 token。

## 非功能需求

### NFR-01：资源与性能

- 保持 8 MB Flash、无 PSRAM 设备适用；不得为本功能新增完整图片副本或完整 HTTP body 缓冲。
- LVGL 对象在初始化时创建并复用，渲染只更新变化内容。
- 新字段固定上限，记录 payload 必须继续小于单槽 `0x20000`。

### NFR-02：兼容性

- 已保存的 schema 1 工牌资料在升级后仍显示相同姓名和照片。
- 网页继续支持常见 iPhone Safari 与 Android Chrome 竖屏操作，不依赖 CDN、远程字体或互联网。
- 普通构建和上传不得写入 NVS、`badge_data` 或 `cardid@0x356000/0x4000`。

### NFR-03：可测试性与验收证据

- native 测试应覆盖：旧/新记录兼容、自定义语句 UTF-8 边界、事务失败回退、协议分块边界、不可用模式跳过、设置电量只读投影。
- Web 逻辑测试或等价脚本应覆盖：自定义语句字节计数/校验、三种遮罩关键像素、已有照片切换形状、envelope 长度与字段编码。
- `pio run` 仅作为目标编译和资源兜底，不作为 UI 功能的唯一验证。
- 真机人工验收应覆盖 240×320 布局、上下键、设置电量、中文自定义语句、iPhone/Android 三种形状、保存后即时刷新和重启恢复。

## 验收标准

1. 冷启动直接展示无顶部栏的工牌，照片、姓名和非空自定义语句完整可见。
2. 当前个性化无内容时，长按上/下均不会离开工牌；长按确认仍可进入设置并正常返回。
3. 设置列表显示最新电量或 `--%`，光标仍只遍历原四个设置项。
4. 网页可以读取、编辑并事务保存姓名、自定义语句和照片；保存后设备无需重启即可刷新。
5. 升级前保存的 schema 1 工牌仍能读取，照片和姓名不变，自定义语句为空。
6. 方形、24 px 圆角和圆形预览与保存后的 LCD 图像一致，圆角/圆形外区在设备上与工牌页背景融为一体。
7. 非法/超长语句、非法姓名、Busy、断连、Flash 写入失败均不发布半成品，上一份完整资料仍可使用。
8. native 新增逻辑测试和目标构建完成；LCD、实体按键、Safari/Chrome、Flash 重启恢复结果单独记录，不以构建替代。

## 范围外内容

- 本期不定义或上传真正的个性化模块内容，也不新增个性化页面编辑入口。
- 不新增照片边框颜色、背景色、任意圆角半径、滤镜、文字颜色或排版模板。
- 不在设备端保存或推断独立的照片形状枚举；形状只体现在最终 RGB565 像素。
- 不增加 BLE、ANCS、AMS、消息、音乐、云端同步、互联网访问或热点密码。
- 不调整 WiFi 生命周期、Flash 分区表、cardid 地址、设置 NVS schema 或电量采样周期。
- 不执行全片擦除或默认烧录；真机烧录和验收需在实现任务明确授权后按保护边界执行。

## 非阻塞实现参数

- 自定义语句上限：96 个 UTF-8 字节，可为空，最多显示两行。
- 圆角照片半径：24 px。
- 遮罩外合成色：设备工牌页背景 `#0B0F0E`（RGB565 量化后与页面背景一致）。
- 当只有工牌可用时，上下键不显示额外提示。

## 待确认问题

无。以上参数可在确认本阶段时直接修订；若不提出调整，将作为后续设计输入。
