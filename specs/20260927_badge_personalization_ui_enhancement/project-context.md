# 项目上下文

> 状态：已确认

## 项目定位

- 当前仓库是 ESP32-C3 的独立工牌展示固件，已实现工牌页、空白个性化页、设置、按需 SoftAP/HTTP 配置网页和事务化工牌存储。
- 用户已确认当前工牌功能和 WiFi 功能真机正常。本规格只改进设备 UI、导航可用性、工牌资料字段和网页端照片形状，不重新设计热点生命周期或拆分固件角色。
- 工作区当前所有工程文件均处于新增/暂存状态，`specs/20260927_badge_core_firmware_migration/` 还有未提交修改。本规格必须保留这些用户现有改动，生产实现只做与本需求有关的最小修改。
- 现有迁移规格 task-01～task-19 已完成，task-20 的正式真机验收记录仍为 `NOT RUN`；用户本轮提供的“工牌功能和 WiFi 功能正常”可作为当前功能基线，但不能代替新改动后的回归验收。

## 技术栈与构建

- 芯片与硬件：ESP32-C3、8 MB Flash、无 PSRAM、240×320 ST7789、ADC 三按键、CW2017 电量计。
- SDK：ESP-IDF 5.5.3，由 PlatformIO `platformio/espressif32@6.13.0` 驱动。
- UI：LVGL 9、`esp_lvgl_port`、项目内 `ui_common` 主题/页面壳和 16 px 中文字体。
- 网络与存储：ESP-IDF SoftAP、HTTP Server、NVS、`badge_data@0x310000/0x40000` 双槽原始 Flash 记录。
- Web：离线 HTML/CSS/原生 JavaScript，浏览器完成照片解码、裁剪、旋转和 RGB565 LE 转换。
- 自动化：PlatformIO native + Unity 覆盖纯 C 逻辑，目标构建使用 `/Users/naaran/.platformio/penv/bin/pio run`；自动化不能替代 LCD、实体按键和手机浏览器验收。

## 当前相关架构

### 公共顶部栏与页面布局

- `components/ui_common/src/ui_shell.c` 当前创建 36 px 公共顶部栏，左侧显示活动模式名称，右侧显示电量；其下 `content` 页面区域为 240×284。
- `main/app_main.c::render_frame()` 每次有效渲染先调用 `ui_shell_update()`，再渲染活动模式。
- 工牌照片当前位于业务内容区 `(20, 8)`，固定 200×200；姓名位于照片下方。默认资料才附带内置文案，用户资料目前只显示姓名。
- 设置页和个性化页也复用同一个公共内容容器。移除顶部栏后应统一重新定义 240×320 的页面可用区域，不能只隐藏标题文本而保留 36 px 空白。

### 导航与个性化占位

- `mode_registry_t.business` 固定注册“工牌”和“个性化”两个模式。
- `navigation_key()` 对长按上/下按数组取模循环，不检查模式是否有内容或是否可进入。
- `custom_mode` 只有稳定 ID/名称，`custom_view` 只显示空白页面；当前没有个性化数据模型、存储、上传接口或内容就绪状态，因此现状下个性化应判定为“无内容”。
- 设置页位于业务循环之外，长按确认进入；退出后通过稳定 `return_id` 返回进入设置前的业务模式。

### 电量与设置

- CW2017 读取在独立 battery task 中执行；`app_controller_t.battery_soc` 保存最近一次 0～100 的有效 SOC，初始/不可用为 `-1`。
- 当前电量只由公共顶部栏消费。`settings_page_t`/`settings_view_t` 尚未接收电量快照。
- 设置列表目前有四个可选项：Wi-Fi 热点、自动息屏、屏幕亮度、返回。将电量移入设置页时应作为只读信息展示，不能误入可编辑设置语义。

### 工牌记录、协议和网页

- `badge_record` schema 1 使用 40 字节头，payload 为“姓名 + 80,000 字节 RGB565 图片”；姓名上限 48 UTF-8 字节。
- 记录头偏移 22 的 16 位字段当前保留且要求为 0，可在新 schema 中用于新增字段长度；旧 schema 1 必须继续可读。
- `badge_store` 使用双槽事务写入、读回 CRC 校验和最后提交标记；资料快照目前只有姓名、图片和序号等元数据。
- HTTP 上传 envelope version 1 为 12 字节头加“姓名 + 图片”，按块流式解析并直接写入非活动槽；`GET /api/profile` 只返回姓名。
- 网页 `app.js`/`badge_image.js` 在 200×200 Canvas 中完成 cover 裁剪、拖动、缩放、90° 旋转和 RGB565 转换。RGB565 没有 alpha 通道，透明预览像素需要在转换时合成到设备工牌页背景色。
- 图片形状可完全由前端在最终 Canvas 像素上应用遮罩并把遮罩外区域合成到设备背景，仍上传固定 80,000 字节图片；设备端无需新增形状字段或渲染分支。

## 可复用能力与差距

| 能力 | 可复用实现 | 当前差距 | 初步决策 |
| --- | --- | --- | --- |
| 页面对象与主题 | `ui_page_create()`、`ui_label_create()`、`ui_theme_*` | 页面高度被公共顶部栏固定为 284 | 扩展公共页面容器为全屏；设置页自行呈现标题和电量 |
| 稳定模式导航 | `mode_t`、`navigation_t`、稳定 ID/return ID | 没有可用性判断，始终进入空白个性化 | 扩展模式可进入判定或导航过滤能力，不在按键层硬编码个性化 ID |
| 电量采样 | battery task、`app_controller_t.battery_soc` | 设置视图拿不到 SOC | 复用现有采样和变化驱动渲染，只投影只读快照到设置页 |
| 工牌双槽存储 | `badge_record`、`badge_store`、`badge_partition` | payload 无自定义语句，schema 只接受 v1 | 演进 schema 并兼容读取 v1；继续原分区与原事务边界 |
| HTTP 流式上传 | `badge_http_protocol`、`badge_http_server` | envelope 无自定义语句 | 演进协议并保持固定上限、分块解析与单事务写入 |
| 图片编辑 | Canvas crop/rotate/RGB565 | 只有方形输出 | 在 Web JS 增加方形/圆角/圆形遮罩，设备端仍接收同一图片格式 |

## 关键约束

- Phase 0～3 只修改本规格目录；确认任务拆解前不修改生产代码。
- 不改变 `badge_data`、`cardid@0x356000/0x4000`、应用分区地址和普通分段烧录边界。
- 旧 schema 1 工牌必须无损读取，缺失自定义语句按空字符串处理；升级不能要求用户重新上传照片。
- 自定义语句必须采用固定上限和合法 UTF-8 校验，不能通过 UI 截断掩盖存储协议不一致。
- HTTP 仍需按块接收，不能在 ESP32 堆上同时保存完整 request body 和图片副本。
- 图片形状只由浏览器端生成最终像素；RGB565 无透明度，形状外区域需要确定固定填充色。
- LVGL 对象仍需一次创建、持锁更新；电量变化仅在设置页可见时造成有效视觉变化，但采样调度保持不变。
- 导航跳过无内容页时不能影响长按确认进入设置、设置返回、息屏唤醒手势消费或 WiFi 专页“任意键退出”。

## 主要风险

- 删除公共顶部栏会同时改变工牌、个性化和设置的父容器尺寸，若只局部改坐标可能造成底部越界、旧区域未刷新或设置行布局失衡。
- 将个性化直接从注册表删除会丢失未来启用入口；将判断硬编码到导航又会降低模式扩展性。需要保留稳定 ID，同时让导航可跳过不可用模式。
- schema/envelope 演进若没有兼容矩阵，可能让已保存工牌回退默认值，或让旧网页缓存提交失败。实现需明确接受版本与缓存策略。
- 自定义语句和更多文本对象会增加 LVGL/font 内存压力；ESP32-C3 无 PSRAM，应控制字节上限、行数和对象数量。
- 圆形/圆角若只用 CSS 改预览而未修改 Canvas 最终像素，LCD 仍会显示方形；自动化需要直接验证输出像素角点。
- 构建/native 测试不能证明 240×320 真机布局、中文语句换行、圆边锯齿观感和 iPhone/Android Canvas 行为。
